The 4-Operator Action Space & Composite Utility Math

Operator Temp Parent Selection Evolutionary Role
DRAFT 0.70 None (root seed) High-entropy architectural exploration from the task specification.
IMPROVE 0.40 1 functional parent (SUCCESS) Algorithmic complexity and inner-loop optimization of a working parent.
DEBUG 0.20 1 broken parent (!= SUCCESS) Deterministic stack-trace repair of syntax, runtime, or timeout failures.
CROSSOVER 0.50 2 distinct parents (parent_a != parent_b) Hybrid recombination of the strongest mechanisms from two working parents.

$$U_i = 0.50 \cdot \text{clamp}\!\left(\frac{s_i - s_{\min}}{s_{\max} - s_{\min}}, 0, 1\right) + 0.35 \cdot \text{clamp}\!\left(\frac{\Delta_i - \Delta_{\min}}{\Delta_{\max} - \Delta_{\min}}, 0, 1\right) + 0.15 \cdot \frac{1}{1 + \text{children\_count}_i}$$

Verified Live on Goliath RTX 4090 (25,000-Element Subarray Benchmark)

Running against live local inference (llama-server.exe on Goliath's RTX 4090) and the isolated Python 3.12 sandbox (sandbox_mode = "local"), rsicraft evolved a 25,000-element maximum contiguous subarray solver (kadane-4090):

1. Step 1 (DRAFT, T=0.70): Synthesized a clean $O(N)$ Kadane baseline scoring 96.5207 (1.391 ms over 80 iterations).

2. Step 4 (CROSSOVER, T=0.50): Sampled two distinct parents (be4fd318 and 56995273), identified that Python's built-in max(x, current_max + x) function-call overhead inside the 25,000-element loop dominated runtime, and replaced both max() calls with inline conditional branching (if current_sum > 0: current_sum += x else: current_sum = x).

3. Result: Execution time dropped to 1.359 ms, advancing the Pareto frontier to 96.6028 (Rank 1, composite_utility = 1.0000).

Why Real RSI Does Not Produce Skynet (We Hope)

Philosophers like Nick Bostrom (*Superintelligence*, 2014) and Eliezer Yudkowsky (MIRI) warned of unconstrained exponential intelligence takeoff ("foom") where a seed AI modifies its own weights into a runaway god-like entity. Real-world empirical RSI refutes this myth through five hard physical realities:

  • Sandbox Execution Bottleneck: Code cannot verify itself in a vacuum; it requires physical CPU/GPU cycles running test suites.
  • Thermodynamic Limits: Goliath consumes 450W and operates within a strict 24.0 GB VRAM ceiling. Allocations exceeding this fail deterministically with CUDA OOM.
  • Algorithmic Lower Bounds: Mathematics cannot be broken. An $\Omega(N \log N)$ sorting bound cannot be evolved into $O(1)$.
  • Stigmergic Transparency: Intelligence is stored in human-readable, cryptographically hashed SQLite WAL + BLAKE3 files, not an inscrutable ghost in the neural weights.
  • Air-Gapped Rootless Sandboxes: Candidates run with --network none, strict memory caps, dropped Linux capabilities, and millisecond timeouts.

3. Core Functional Requirements

1. 4-Operator Evolutionary Action Space (operators.rs):

  • DRAFT (T = 0.70): High-entropy baseline synthesis from raw problem specifications.
  • IMPROVE (T = 0.40): Algorithmic and constant-factor optimization of a sampled SUCCESS parent.
  • DEBUG (T = 0.20): Stack-trace-driven repair of a sampled broken parent (COMPILE_ERROR, RUNTIME_ERROR, TIMEOUT).
  • CROSSOVER (T = 0.50): Recombination of two distinct high-utility parents (parent_a != parent_b).

2. Composite Utility Parent Selection (store/utility.rs):

  • $U_i = 0.50 \cdot s_{\text{norm}, i} + 0.35 \cdot \Delta_{\text{norm}, i} + 0.15 \cdot \frac{1}{1 + \text{children\_count}_i}$.
  • Stochastic roulette-wheel sampling proportional to $U_i$.

3. Stigmergic SQLite WAL + BLAKE3/Zstd CAS (store/mod.rs, store/cas.rs):

  • 256-bit BLAKE3 content hashing + Zstd level-3 compression of candidate source code.
  • Materialized task_frontiers table tracking the top-K Pareto frontier per task.

4. Extended Tooling & Multi-Language Sandboxing:

  • Line-by-line unified code diffing (rsi_diff) between CAS experience cards.
  • Active LLM endpoint reachability and latency probing (rsi_llm_probe).
  • Runtime composite utility hyperparameter inspection and tuning (rsi_hyperparams_get, rsi_hyperparams_set).
  • Complete task lineage JSON export and import bundles (rsi_export, rsi_import).
  • Cascading task deletion (rsi_task_delete) and Pareto frontier card pruning (rsi_cards_prune).
  • Native Rust compilation and evaluation (rustc --crate-type=rlib) alongside Python 3.12.

3. Evolutionary Execution & Multi-Language Sandbox Tools

rsi_step (CLI: rsicraft step)

Executes a single evolutionary step:

1. Samples 0, 1, or 2 parents from the SQLite WAL store using composite utility $U_i$.

2. Builds operator-specific prompts (DRAFT 0.70, IMPROVE 0.40, DEBUG 0.20, CROSSOVER 0.50).

3. Queries llama-server (provider = "llama") or the deterministic oracle (provider = "demo").

4. Evaluates synthesized code in sandbox_mode ("docker", "local", or "demo").

5. Compresses code via BLAKE3 + Zstd, records the experience card, recalculates $U_i$ across the task, and refreshes task_frontiers.

rsi_campaign (CLI: rsicraft campaign)

Runs steps (1..=64) autonomous evolutionary steps cycling across DRAFT -> IMPROVE -> DEBUG -> CROSSOVER and returns the full trajectory and best score.

rsi_evaluate (CLI: rsicraft evaluate)

Directly benchmarks a candidate snippet against a task's evaluator in the sandbox (record = true by default). Automatically supports both Python 3.12 and native Rust compilation (rustc compiling candidate.rs + evaluator.rs).

rsi_demo_seed (CLI: rsicraft demo-seed)

Seeds an empty database with the opt-synth (Vector Max) benchmark task and a 4-card evolutionary progression (DRAFT -> DEBUG -> IMPROVE -> CROSSOVER).

4. Frontier, Lineage DAG, Diff & Prune Tools

rsi_get_frontier (CLI: rsicraft frontier [--task-id <id>] [--limit <k>])

Returns the materialized top-K Pareto frontier experience cards for a task.

rsi_card_list (CLI: rsicraft cards [--task-id <id>] [--operator <op>] [--status <st>])

Lists experience cards ordered by composite utility $U_i$, with optional operator and execution-status filters.

rsi_card_show (CLI: rsicraft card <card_id>)

Decompresses the Zstd payload, verifies the BLAKE3 hash, and returns the full experience card including source code and sandbox stdout/stderr.

rsi_lineage (CLI: rsicraft lineage [--task-id <id>])

Exports the complete evolutionary lineage DAG (nodes and parent_a/parent_b edges) for graph visualization.

rsi_diff (CLI: rsicraft diff --card-a <id> --card-b <id>)

Generates a line-by-line unified text diff comparing decompressed source codes between two experience cards (e.g. parent vs child candidate).

rsi_cards_prune (CLI: rsicraft prune --task-id <id> [--keep-frontier <k>])

Prunes low-utility non-frontier cards for a task, keeping at least keep_frontier top Pareto cards while maintaining database cleaniness.

5. Runtime Hyperparameter Tuning Tools

rsi_hyperparams_get (CLI: rsicraft hyperparams)

Returns current composite utility weights ($\lambda_s, \lambda_\delta, \lambda_\nu$) used for stochastic parent selection.

rsi_hyperparams_set (CLI: rsicraft hyperparams [--w-score <s] [--w-delta <d>] [--w-novelty <n>])

Dynamically adjusts composite utility weights ($\lambda_s, \lambda_\delta, \lambda_\nu$) at runtime without restarting the daemon.
